\begin{abstract}
This document walks through the literal console output of one full
\texttt{make all} run (validate $\to$ split $\to$ eval-harness $\to$ test
$\to$ stats $\to$ plots $\to$ baselines, run 2026-08-19, all 10 stages
completed with no errors) and discusses what each stage's numbers mean.
Where \texttt{report/report.tex} presents the polished, aggregated
narrative, this document keeps the per-fold detail that report intentionally
compresses away, since that detail turns out to carry a real finding: fold
composition, not separation method, explains most of the fold-to-fold
variance in the results. As in \texttt{report.tex}, every number here is
computed on the current, provisional (GitHub-sourced, not yet
Mendeley-verified) copy of HLS-CMDS.
\end{abstract}

\section{Stage 1: Dataset Validation (\texttt{make validate})}
% ============================================================

\texttt{load\_dataset.py} loaded all three manifests and resolved every
referenced audio file:

\begin{verbatim}
HS:  50 rows, all audio files found
LS:  50 rows, all audio files found
Mix: 145 rows, all audio files found
Sample rate: 4000 Hz
Additivity check (mixed ~= a*(heart+lung)): 36/145 rows additive
\end{verbatim}

\textbf{Discussion.} The first three lines are a pure integrity check ---
every row's audio exists and is readable --- and are unremarkable on their
own. The last two lines are not: 4000\,Hz does not match the 22{,}050\,Hz
the HLS-CMDS descriptor paper documents, and only 36 of 145 mixture rows
are acoustically related to their own named heart/lung sources. Both are
symptoms of the same root cause (this working copy is sourced from a
GitHub mirror, not the Mendeley release the project specifies) and both
propagate into every later stage's numbers. This is the single most
important fact to carry forward from this run: nothing below should be read
as a claim about HLS-CMDS itself until it is re-verified on the correct
dataset copy.

\subsection{Cross-baseline fold correlation}
\label{sec:foldcorr}

Because Baseline~1 and Baseline~2 use the same fold assignment within each
row set (Section~\ref{sec:baselines}), their per-fold numbers are directly
comparable fold-by-fold. Ranking the full-145 folds by heart SDR:

\begin{itemize}
  \item Baseline 1: fold 2 (best) $>$ fold 3 $>$ fold 4 $>$ fold 0 $>$ fold 1 (worst)
  \item Baseline 2: fold 2 (best) $>$ fold 3 $>$ fold 4 $>$ fold 0 $>$ fold 1 (worst)
\end{itemize}

\noindent The order is \emph{identical}. The same comparison on the 36-row
valid subset:

\begin{itemize}
  \item Baseline 1: fold 1 (best) $>$ fold 2 $>$ fold 4 $>$ fold 3 $>$ fold 0 (worst)
  \item Baseline 2: fold 2 (best) $>$ fold 1 $>$ fold 4 $>$ fold 3 $>$ fold 0 (worst)
\end{itemize}

\noindent Folds 1 and 2 swap at the top, but fold 0 is worst and fold 3 is
second-worst in both. Lung SDR shows the same qualitative pattern with
fold~0 worst in three of the four method/row-set combinations
(the exception is Baseline~2 on the full set, where fold~0 is worst by an
even larger margin).

\textbf{Discussion.} With only 5 folds this is not a statistically rigorous
claim, but the consistency is striking: \emph{which fold a row lands in}
predicts separation quality about as well as \emph{which of the two methods}
processed it. The most direct explanation is that folds differ in how many
genuinely additive rows they contain (Section~1) and/or in which heart/lung
classes dominate them, and that this per-fold composition effect is larger
than the gap between a zero-training filter and a fitted NMF dictionary.
This is a caution for any future baseline comparison on this dataset: a
single fold's number is not informative about method quality on its own,
and a new method should be checked for the same cross-fold ranking pattern
before its aggregate score is trusted.

\section{Discussion}
\label{sec:discussion}
% ============================================================

Pulling the seven stages together:

\begin{enumerate}
  \item \textbf{The pipeline itself is healthy.} All 10 \texttt{make all}
    targets completed without error, all 31 tests pass, and the harness's
    plumbing smoke test (Section~\ref{sec:evalharness}) confirms the fold
    $\to$ fit $\to$ score $\to$ aggregate path works correctly end-to-end.
    Nothing in this run indicates a code-level bug.
  \item \textbf{The dataset is not yet trustworthy.} 109 of 145 mixture rows
    have no genuine heart+lung structure to separate (Section~1), and the
    sample rate itself is off by 5.5$\times$ from the documented value ---
    both symptoms of sourcing this working copy from GitHub instead of
    Mendeley. Every quantitative result below the dataset caveat is
    provisional.
  \item \textbf{Restricting to genuinely valid rows changes the story, not
    just the scale.} SDR jumps 15--18\,dB once the 109 invalid rows are
    excluded (Section~\ref{sec:baselines}) --- expected, since those rows
    have nothing coherent to separate --- but more importantly, the
    \emph{ranking} of the two baselines flips from a near-tie (full set) to
    a clear, consistent win for the zero-training bandpass filter over
    learned NMF (valid subset). A comparison run only on the full,
    mostly-invalid set would have reported the wrong qualitative
    conclusion, not just a noisier version of the right one.
  \item \textbf{Fold composition is a bigger effect than it looks.}
    Section~\ref{sec:foldcorr}'s fold-ranking agreement between two
    unrelated separation methods suggests a meaningful share of the
    fold-to-fold variance reported as ``std'' in \texttt{report.tex}'s
    aggregate tables reflects which rows are in each fold, not method
    instability. This does not change any reported number, but it does
    change how those numbers should be read: as method comparisons that are
    only as reliable as the row composition they share, not as independent
    per-fold measurements of method quality.
\end{enumerate}
